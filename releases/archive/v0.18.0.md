上一次发布是 v0.17.1（通知体系）。这一版解决的是「执行完了到底成没成、我该不该等它」和「界面太长」这两类问题。

## 新增：知道对方是谁，也知道它回了什么

- 执行时先判断目标是 **机器人 / 用户 / 群组 / 频道**（`classifyPeer()`），日志第一行写「目标类型：机器人」
- **最后一步之后会等对方的第一条回复**。以前只有「带按钮的消息」会被等到，纯文本签到机器人（`签到成功` 这类）根本等不到：
  - 机器人 → 它回的文本
  - 群组 → 最后一步之后**别人**发的第一条（自己发的不算）
  - 普通用户 → 对方回的第一条
- 拿到后写进日志 `▶ 回复：…`、任务「最近结果」变成 `执行完成 · 收到回复「签到成功」`；
  配了 `#kw:` 的任务改用这段回复做关键词判定
- 只有「最后一步是发文本/随机/数字」或「配了关键词」才多等一次，纯点按钮的流程不额外加延迟

## 新增：任务上标出类型

- 任务列表目标列前显示彩色徽章：机器人（青）/ 群组（蓝）/ 频道（紫）/ 用户（灰）
- 任务详情多一行「目标类型」；未解析过的任务显示「未知（下次执行时自动识别）」
- 编辑器点「解析」后，结果里也带类型
- 类型在解析目标时自动写入（建任务、触发器、首次执行都会补），老任务不用手动改

## 修复：任务名不会再被系统改掉

手动建的任务在执行时曾被系统改名（`123456789 签到` → `示例机器人`）——因为执行阶段的"目标补全"会顺带改名。
现在：

- 目标信息（显示名 / access_hash / 类型）**只在建任务那一刻补全**（指令识别、编辑器解析）；
  执行阶段只补"解析必需"的字段，**绝不碰任务名**，日志改成「补齐目标信息：…（任务名不会被改动）」
- 新增 `Task.nameAuto`（DB 列 `name_auto`）：
  - `true`：名字是系统按目标生成的，可以跟着目标变
  - `false`：用户自己起的（编辑器动过名字框 / 指令写了 `#name:`），**永不改**
  - `NULL`（老任务）：只有名字仍等于系统默认名时才允许改，手动改过名的老任务不受影响

## 修复：钉钉 / 企业微信的日报版式

这两家的 markdown **不支持表格**，原来用「`**指标**：值` + 两空格硬换行」堆两列，备注还会被挤成一行。现在改成一行汇总 + 单层列表，与日志里的纯文本版式对齐：

```
### 📊 签到日报 10/25

**执行 2 次：成功 0 · 失败 2（成功率 0%）**

- 失败任务：样本2、样本1
- 任务 2 个（启用 2）
- 下次执行 10/25 23:51
```

企业微信不支持 `###` 标题，自动降级成加粗；飞书卡片不变（两列 `fields` 本来就是它最擅长的）。

## 新增：有副作用的操作都加二次确认

立即执行 / 停用任务 / 删除任务 / 运行全部 / 退出管理界面，现在都会先弹确认框，说明会发生什么：

- 立即执行：「会用当前配置真发到 Telegram，手动执行不打乱定时」
- 停用：「不再按计划执行，配置和日志保留，随时可以再启用」（启用不弹，没副作用）
- 删除：「不可恢复，这个任务的执行日志也会一并删掉」
- 退出管理界面：「要重新输口令；签到任务照常执行」

顺手修了删除任务的旧文案——原来写「历史日志会保留」，实际服务端会一起删掉。

## 改版：设置页拆成二级 tab

执行 / 消息指令 / 登录与安全 / 关于。原来一页滚到底，「登录与安全」那一屏超过 4000 px，现在最长约 2300 px：

- 非当前 tab 只是隐藏，保存时仍一次提交全部字段
- 记住上次停留的 tab；支持 `←` `→` 切换（`role=tablist` / `aria-selected`）
- 移动端 tab 条可横向滚动，375px 无横向溢出
