> 这是本项目**第一个正式发布**。此前 48 个版本迭代（0.1.0 → 0.17.1）的内容都已整合进这个版本，
> 下面的清单按「能力」组织，而不是按版本号。

Telegram 自动签到系统，整套跑在 **Cloudflare Workers + 单个 Durable Object** 上：
没有 VPS、没有常驻进程、没有数据库服务。session / 任务 / 日志全部在 DO 内嵌 SQLite 里，
运行时只依赖 `teleproto` 一个库（MTProto 客户端），前端是零构建的原生 JS。

## 一、怎么用：三种建任务方式

| 方式 | 说明 |
| --- | --- |
| 发一条消息 | 往收藏夹（或指定会话）发 `tg 9.30 签到` 即建任务；`tg 列表` / `tg 删除 3` / `tg 帮助` 也能用 |
| 管理界面 | 任务页「新建任务」，表单式配置：目标 → 调度 → 动作流水线 |
| 从模板 | 内置 4 个模板（每日打卡 / 两级菜单签到 / 每日随机问候 / 群里定时提醒），也可把当前配置「存为模板」 |
| 从指令粘贴 | 任何任务都能导出成等价指令（「复制指令」），粘到收藏夹即重建；导入导出 JSON 用于备份迁移 |

## 二、指令语法（`tg` 前缀可关）

- **时间**：`9.30` `09:30` `0930` `9点半` `21点15分`；窗口 `8.30-10.30`（窗口内随机）；间隔 `每30分` `每2小时`；`once` 只跑一次
- **动作**：文本 → `btn:按钮文字`（也支持 `btn:行,列`）→ `num:数字` → `rand:选项1|选项2` → `wait:秒` → `say:` 强制当文本
- **修饰符**：`#kw:关键词1|关键词2`（成功判定）、`#thread:12`（话题）、`#jitter:300`（随机延迟）、`#delay:5`（步骤间隔）、`#timeout:45`、`#delete:60`（发完删）、`#keep`（不清理上次消息）、`#once`、`#name:自定义`
- **目标**：`@bot` / `-1001234` / `t.me/xxx` / `@here`（当前会话）/ `到:@a|@b`（多目标，最多 8 个）/ `@group#12`（目标自带话题）
- 指令与任务**互为反函数**：导出的指令可以原样解析回等价任务（19 个往返用例守着，含引号转义）

## 三、执行能力

- 多步骤：发文本 → 轮询机器人回复 → 按文本/行列点按钮 → 下一层菜单 → 关键词判定成功
- 按钮类型：callback、reply keyboard（按文本发送）、带图标的按钮文本（`👤 个人资料` 可匹配 `个人资料`）
- 清理与回收：默认执行前删掉上次自己发的消息（`#keep` 关闭）、可选发完 N 秒删除
- 多目标：一次执行依次跑完所有目标，任一成功即算成功，每目标单独记日志
- 时间预算：单个任务最多 30 秒 ~ 4 分钟（按步骤估算），超预算停止并如实记录，不会跑到被驱逐
- 失败处理：连续 3 次失败自动暂停，避免天天失败还一直跑

## 四、调度与可靠性

- DO alarm 精确调度（下次执行时间落库），Workers cron 每 5 分钟兜底
- 每天类任务有硬约束：`daily` / `window` / `once` 一天只跑一次；另有 45 秒重复执行护栏
- 触发器轮询按批回溯（100 条 × 最多 5 批、按 id 去重），短时间连发大量指令不会丢
- 连接只在 30 秒内复用，空闲主动断开；只对**连接类**错误重连重试，业务错误不重放副作用
- 手动执行不打乱定时；`run-all` 分批执行（返回 `nextOffset` / `remaining`），任务多也不撞网关超时

## 五、通知

**11 种通知类型可多选**（默认只开关键几项，其余按需勾）

> 执行失败 · 连续失败自动暂停 · 失败后恢复 · 会话过期 · 连接异常 · 登录失败 · 执行成功 ·
> 日报 · 周报 · 存储告警 · 成功率告警

**4 个渠道，选好渠道之后只需要填机器人 Token**（地址由程序固定生成）

| 渠道 | 填什么 | 送达格式 |
| --- | --- | --- |
| 钉钉自定义机器人 | 机器人 access_token（支持加签） | Markdown |
| 企业微信群机器人 | 机器人 Key | Markdown |
| 飞书自定义机器人 | 机器人 Token | 交互卡片（两列指标 + 明细 + 备注） |
| 自定义渠道（自建） | 完整 Webhook 地址 | 通用 JSON |

细节：

- 日报：当天执行次数 / 成功率 / 失败任务 / 下次执行；周报：**本周 vs 上周**对比 + 失败最多任务 Top5
- 成功率告警：最近 7 天成功率低于阈值（默认 80%）就提醒——专治「偶尔失败、连续失败计数到不了 3」
- 存储告警：DO 存储用量超过阈值（默认 70%）提醒，关于页也能看到当前占用
- 钉钉 / 企微 / 飞书**出错也返回 HTTP 200**，所以会解析 `errcode` / `code` 并落日志，不会把"没发出去"记成成功
- 「发送测试通知」用表单里**当前填的值**真打一遍（不用先保存），并回显打码后的推送地址
- 敏感值（Turnstile Secret、钉钉加签密钥）只存服务端，接口永不回传，只给「已配置」标记

## 六、管理界面

- 5 个页面：概览 / 任务 / 日志 / 账号 / 设置；**全局只用弹窗，无抽屉**，375px 可用
- 概览：快速开始清单、连接状态一句话、近 7 天执行趋势、用量统计
- 任务详情弹窗：最近 5 次运行、查看全部日志、编辑、立即执行、复制指令
- 日志：按级别 / 任务 / 时间范围（近 1 小时 / 24 小时 / 7 天）筛选 + 关键字搜索 + 页码分页；
  失败日志展开可直接跳去「去登录 / 编辑任务 / 调整关键词 / 重试一次」
- 复制指令三级回退：`navigator.clipboard` → `execCommand` → 兜底弹窗（http 环境、旧浏览器也能复制）

## 七、安全

- 口令 + HMAC 签名的 HttpOnly Cookie（7 天），同 IP 10 次失败 / 10 分钟锁定（计数落在 DO SQLite，多机房一致）
- 状态变更接口校验 `Origin`，配合 `SameSite=Lax` 做 CSRF 纵深防御
- CSP / nosniff / X-Frame-Options / Referrer-Policy / Permissions-Policy / HSTS，`script-src 'self'`
- 可选 **Cloudflare Turnstile**（设置页填写，保存即生效；校验失败按 fail closed 处理）
- 请求体 64 KB 上限，所有输入长度收敛（任务名 80 / 步骤文本 500 / 关键词 20×60 …）
- 错误只返回中文可读信息，SQLite / 驱动层原文不外泄
- 建议叠一层 **Cloudflare Access**，并把 `ALLOWED_HOSTS` 设成你的自定义域名（否则 `workers.dev` 会绕过 Access）
- 威胁模型与渗透实测记录见 `SECURITY.md`

## 八、一路上修掉的关键问题

- **窗口任务连发**：窗口模式执行完仍从"窗口内随机"算下次 → 现在执行后跳到下一个窗口 + 每天只跑一次的硬约束 + 45 秒护栏
- **主目标被顶掉**：多目标任务首次执行补全目标时把主目标换成了第二个 → 只有主目标能写 `target` 与改名
- **任务判重漏了附加目标**：`到:@a|@b` 与 `到:@a|@c` 被判重复 → 指纹纳入多目标
- **指令不可往返**：文本以 `#` / `btn:` / 时间 / 链接开头、随机项与关键词含空格、名称含引号 → 现在用 `say:` + 统一引号转义
- **按钮点不动**：layer 232 的 inline 按钮结构换成 `KeyboardInlineButton { type: { data } }`，新旧两种都认
- **`Could not find the input entity`**：数字 id 需要 access_hash → 优先 `@username`、三层兜底（直接解析 / `getDialogs` 预热 / 对话列表按 username 找）
- **`PHONE_MIGRATE_n`**：自动切到账号归属 DC 并记住
- **点操作图标也弹详情**：SVG 元素不是 `HTMLElement`，守卫失效 → 改用 `Element` + `data-no-row-click`
- **触发指令丢失**：轮询只取最近 20 条 → 按批回溯
- **复制失败**：只有 clipboard 一条路 → 三级回退
- **线上 "does not export class 'TgAgent'"**：`npm run deploy` 前自检产物导出

## 九、行为变化（从很早期版本升级时注意）

- 触发前缀默认变成 `tg`（空字符串 = 解析全部消息）；忘记前缀且看起来像配置时会提醒一次
- `cleanupPrevious` 默认开启（每次执行前删上次自己发的消息），`#keep` 关闭
- 新的历史部署会补默认值：`notifyEvents`、`notifyWebhookKind`、`digestHour` / `weeklyHour`、存储与成功率阈值；
  以前填过完整 Webhook 地址的不受影响，只填了 `access_token` 的会被自动补全成完整地址
- 登录态有效期 7 天；日志只保留最近 2000 条；单次执行最多等 300 秒

## 十、已知限制

- 单账号、单 Durable Object
- `url` / `webview` / `switch_inline` 按钮会跳过并记日志（不做真实点击）
- 触发消息最多延迟一个轮询周期（默认 60 秒，最低 15 秒）
- Telegram 限流（flood wait）直接失败并记日志，不做长时间等待
- 时区用固定 UTC 偏移，不处理夏令时
- DO 被驱逐时执行会中断（日志可见，下一次 alarm 重连继续）

## 部署

```bash
git clone https://github.com/mihucho/cf-tg-checkin.git && cd cf-tg-checkin
npm ci
npx wrangler secret put ADMIN_PASSWORD     # 管理界面口令（建议 openssl rand -base64 24）
npm run deploy
```

已有部署升级：`npm run deploy` 或 push 到 `main`（CI 会先跑 typecheck + 单测 + 集成 + 产物自检）。
数据无需迁移：schema 改动都是幂等的 `ALTER TABLE ... ADD COLUMN`。
部署后确认版本：`curl https://<你的域名>/api/version`。
