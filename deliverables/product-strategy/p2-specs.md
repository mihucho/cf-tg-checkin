# P2 详细规格

前置：P0（0.5.0）与 P1（0.6.0）已落地。以下 6 项是评审里的 P2，按**依赖与风险**排序，不建议按编号顺序做。

---

## P2-3 设置页重组（先做，0.5 天）

**现状**：一屏平铺 12 个字段 + 3 个分区标题，顺序跟代码里的字段顺序一致（时区 → 检查间隔 → 按钮等待 → 消息指令 → 登录验证）。

**目标结构**（4 组，可折叠，折叠状态存 localStorage）：

| 分组 | 字段 |
| --- | --- |
| **执行** | 时区（UTC 偏移）、按钮等待：检测间隔 / 等待上限 |
| **消息指令** | 开关、指令来源、指令前缀、管理员 ID、检查间隔 |
| **登录与安全** | 登录验证（Turnstile 三件套）、失败提醒（开关 / Webhook） |
| **关于** | 版本、出口机房、DO 区域、仓库链接、文案规范链接 |

**交互**：
- 分组标题可点击折叠，右侧显示该组"已改动"标记（与保存按钮联动）
- 底部固定「保存设置」条（长表单滚动时始终可见）
- 危险项（清除 Turnstile 私钥）仍在组内，不与保存混在一起

**验收**：375px 无横向滚动；Tab 顺序 = 视觉顺序；保存后分组状态不丢。

## P2-5 键盘可达性（0.3 天，与 P2-3 同批）

| 问题 | 修法 |
| --- | --- |
| 顶部 tab 没有当前页语义 | 加 `aria-current="page"`；保持 `<a href>` 天然 Tab 可达 |
| 日志行展开 | 已是 `<button>`；补 `aria-controls` 指向详情 `<pre id>`，Enter/Space 均可触发（原生行为） |
| 任务表格行整行可点，键盘到不了 | 行内「详情」按钮已存在（保持）；行点击只是鼠标便利，不做 tabindex |
| 抽屉/弹窗关闭后的焦点 | 确认 `closeModal` 回到触发元素；编辑器抽屉关闭后应回到「编辑」按钮 |
| 跳转提示 | toast 已有 `aria-live`；错误用 `role="alert"` 已覆盖 |

**验收**：只用键盘走完「登录 → 建任务 → 立即执行 → 打开日志详情 → 关闭（焦点回到原按钮）」。

## P2-1 模板库（0.5 天）

**入口**：
- 任务页空状态：「从模板开始」
- 新建任务抽屉顶部：「从模板开始（可选）」一行 chips

**模板（4 个，纯前端静态数据）**：

| 模板 | 预填内容 | 用户只需填 |
| --- | --- | --- |
| 每日打卡 | 单文本「签到」+ `#kw:签到成功` | 目标、时间 |
| 两级菜单签到 | `/start` → `btn:个人资料` → `btn:签到` + `#kw:签到成功` | 目标、时间、两个按钮文字 |
| 每日随机问候 | `rand:早上好\|午安\|晚上好` + 窗口 08:30–10:00 | 目标（群里可 `@here`） |
| 群里定时提醒 | 文本 + `@here` + 每天 09:00 | 文本 |

**行为**：选模板 → **预填编辑器**（不直接建任务）。理由：目标必须用户给，且让用户看到结构化配置优于黑盒创建。
编辑器底部的「等价指令」会实时显示，等于顺带教了指令语法。

**数据**：模板直接写成 `{ name, command, needs: ["target","time"] }`，用 `parseTrigger` 解析后填入表单 →
模板与 DSL 永远一致（单测：每个模板的 command 都能被解析）。

**验收**：从点「模板」到保存 ≤3 次交互；4 个模板各有一条单测。

## P2-2 一个任务多目标（1.5 天，改动面最大）

**为什么值得做**：现在同一套动作发给 3 个群要建 3 个任务，容易漏改（也更容易踩重复创建/重复发送）。

**数据模型**：
- `tasks.target` 保留为主目标（兼容老数据、老 API）
- 新增 `tasks.targets TEXT`（JSON 数组，含主目标；为空时视为 `[target]`）
- 指令语法：`到:a|b` 与 `@a|b`（`@here` 不参与多目标）

**执行语义**：
- 一次调度运行覆盖所有目标，按顺序执行；**每个目标写一条日志**（`taskName` 追加 `→ @目标`）
- 熔断按任务整体：**所有目标都失败**才累加 `fail_streak`；任一成功则清零
- 失败提醒聚合为一条：`3 个目标里 1 个失败：@groupB 未匹配关键词`

**UI**：
- 编辑器目标区改为列表（添加/删除，第一项为主目标）
- 任务列表目标列显示 `@a +2`，悬停列出全部
- 任务详情展示每个目标最近一次结果

**风险**：
- 执行时间随目标数线性增长（3 个目标 ≈ 3 倍），需给编辑器提示"目标越多越慢"，并限制 8 个以内
- 与 `#thread`（话题）组合时，不同目标可能话题 ID 不通用 → 规则：`threadId` 仅对主目标生效，其余目标忽略并记一条 warn

## P2-6 最小埋点（0.3 天，可选）

**目的**：评审里的验收指标现在无法度量。

- 事件：`first_login`、`task_created{source=ui|trigger}`、`run_finished{ok}`、`failure_handled{action}`
- 存储：DO SQLite `events(name TEXT, at INTEGER)`，只增不删（每类保留最近 5000 条）
- 展示：「关于」里显示几张计数（首次登录耗时、指令建任务占比、失败处理率），不采集任何内容
- 隐私：只记录事件名与时间戳，不记录消息文本、任务名

## 建议执行顺序

| 顺序 | 项 | 工作量 | 理由 |
| --- | --- | --- | --- |
| 1 | P2-3 设置页重组 + P2-5 键盘可达性 + P2-4 移动端 | 1.3 天 | 纯前端、低风险，一次性把"质感"补齐 |
| 2 | P2-1 模板库 | 0.5 天 | 直接提升首次成功率，且依赖已完成 |
| 3 | P2-6 埋点 | 0.3 天 | 有了它才能验证前面所有改动的效果 |
| 4 | P2-2 多目标 | 1.5 天 | 改动最大，建议单独一轮 + 单独发版 |

> 合计约 3.6 天。P2-2 建议独立成 0.7.0，其余可合为 0.6.x 系列。
