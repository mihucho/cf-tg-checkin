# 界面文案规范

> 这份文件是为了让后面的改动**不把文案带回去**。改 UI 文字前先看一眼。

> 有 `scripts/copy-lint.mjs` 兜底：`npm run check` 会跑，违反下面「不要出现」清单直接失败。

## 语气

- 面向"会用 Telegram、但不想懂实现"的人。**说它是什么、怎么影响行为**，不解释内部机制。
- 不用感叹号、不卖萌、不用"哦/啦/呢"。不用「请」堆礼貌，一句话说清即可。
- 中文全角标点；数字和单位之间不留空格（`3 秒` 写 `3 秒`，但括号里用半角：`（秒）`）。

## 专有名词的写法

| 写这个 | 不写 | 备注 |
| --- | --- | --- |
| Telegram | TG、tg（指平台时） | 顶栏窄屏也写全「未登录 Telegram」，不缩写 |
| 机器人 | bot | URL 里的 `bot` 除外（`open.feishu.cn/…/bot/v2/hook`） |
| 收藏夹 | self | 「指令来源」填 `self` 时界面显示「收藏夹」 |
| 人机验证 | 验证码组件 / Turnstile widget | 品牌名可保留：Cloudflare Turnstile |
| Webhook（推送地址） | 回调、hook | 第一次出现写全，后面用「Webhook」 |
| 应用 ID / 应用密钥 | apiId / apiHash | 技术名只放在提示语里（"my.telegram.org 里叫 api_id"） |
| 部署区域 | DO 区域、Durable Object | |
| 从 0 开始 | 0 基 | 按钮行列编号 |
| 执行 | 运行 | 见下方动词表 |

## 动词表（按钮/操作）

| 场景 | 用 |
| --- | --- |
| 立刻跑一个任务 | 「立即执行」 |
| 跑所有任务 | 「执行全部」 |
| 检查有没有到期任务 | 「立即检查」 |
| 停掉调度 | 「停用」／恢复用「启用」 |
| 删除 | 「删除任务」「清空日志」 |
| 保存 | 「保存设置」／编辑器里是「保存任务」 |
| 复制 | 「复制指令」「复制示例」「复制这段内容」 |
| 验证通知 | 「发送测试通知」 |

同一个动作全站只用一个词：不要「运行」和「执行」混着来。

## 配置项命名

**名词短语 +（单位）**，不要"多久做一次"这种口语化的动词句。

| ✅ 正确 | ❌ 避免 |
| --- | --- |
| 检查间隔（秒） | 多久检查一次新消息（秒） |
| 检测间隔（秒） | 每隔多久看一次（秒） |
| 等待上限（秒） | 最多等多久（秒） |
| 时区（UTC 偏移） | 时区（小时） |
| 指令来源 | 去哪里读指令 |
| 管理员 ID | 管理员 Telegram ID |
| 步骤间隔（秒） | 两步之间间隔（秒） |
| 定位方式 | 怎么找按钮 |

## 目标里的 `#话题`

`@group#12` 表示「这个群的话题 12」，只对该目标生效；任务的全局 `#thread:12` 仍然作为默认值。

## 术语表（统一说法）

| 实现里的词 | 界面上的说法 |
| --- | --- |
| MTProto / 会话 / session | Telegram 连接 / 登录状态 |
| 触发器 / trigger | 消息指令 |
| 轮询 / polling | 检查（"检查间隔"） |
| 步骤检测 / stepWait | 按钮等待 / 检测间隔 |
| 动作流水线 / steps | 执行步骤 |
| DSL / 触发语法 | 指令写法 |
| 凭据 / credentials | 应用信息（应用 ID / 应用密钥） |
| 落库 / 写入数据库 | 保存 |
| 解析 / parse | 识别 / 解析（"指令试算"里可用） |

字段的技术名（`controlChat`、`adminUserId`、`triggerPrefix` …）**不要出现在标签里**；
确有必要时放在提示语末尾，或者干脆省略（README / docs 里会写）。

## 数字与标点

- 数字和中文单位之间留一个空格：`每 60 秒检查一次`；括号里的单位不留：`检查间隔（秒）`
- 中文里一律全角标点 ，。；：（）；代码、指令、URL、文件路径用半角并放在 `code` 样式里
- 界面文案不用感叹号；不用「哦/啦/呢」
- 列表里的示例值（占位符）用中文顿号或逗号分隔：`签到成功，已签到`

## 提示语（hint）

一句"它是什么"，必要时加一句"会影响什么"。控制在 40 字内。

```
✅ 读取新消息的频率。越短越及时，但请求量也越大。
✅ 仅该 Telegram 账号发出的指令有效。指令来源改为群组时建议填写。
✅ 超过该时长仍无下一步按钮，则判定这一步失败。
❌ 越小越及时，但会消耗更多请求。        （"请求"是开发者词）
❌ 只有这个 id 能通过消息命令管理任务，留空表示不校验。（主谓宾像文档，不像界面）
```

## 按钮与状态

- 按钮：2–4 字动词短语 ——「新建任务」「运行全部」「立即执行」「保存设置」「清空日志」。
- 状态：短名词 + 标点 ——「运行中」「已关闭」「空闲（需要时自动连接）」「已连接」。
- 危险操作必须二次确认，确认文案要说清后果：`退出后会清除登录状态，定时任务在重新登录前不会执行。`

## 空状态

一句话说明**为什么是空的** + 一条**下一步该做什么**，不要只写"暂无数据"。

```
还没有执行记录
手动运行一次，或在收藏夹里发条指令试试。
```

筛选导致的空状态要与"真的没有数据"区分，并提供一键清空筛选。

## 不要出现（`npm run lint:copy` 会拦）

| 不要写 | 改成 |
| --- | --- |
| `TG` | `Telegram` |
| `bot`（作为"机器人"讲） | `机器人` |
| `self` | `收藏夹` |
| `DO` / `Durable Object` | `部署区域` |
| `0 基` | `从 0 开始` |
| `apiId` / `apiHash` / `controlChat` / `adminUserId` / `triggerPrefix` / `pollSeconds` / `taskId` | 人话描述，技术名放提示语末尾或省略 |
| `！` | 删掉 |
| 中文里的半角 `(` `)` `,` | `（` `）` `，` |

## Telegram 里的消息（帮助 / 回复 / 提醒）

这些也是界面文案，同一套规则，只是没有样式可用：

- 用 emoji 做状态前缀（`✅` `⏸️` `❌` `🗑️` `ℹ️`），不加感叹号
- 任务编号统一写成 `#12`，任务名用直角引号包起来：`已删除任务 #12「每日签到」`
- 时间带时区：`下次执行 10/25 09:30（UTC+8）`
- 帮助文本按「时间 / 要做的事 / 附加设置 / 发给谁 / 管理任务 / 例子」分段，
  段内用 ` · ` 开头列出写法，示例直接给可直接复制的指令
- 报错要说「缺什么 + 怎么补」：`缺时间：在最前面写上几点执行，例如「9.30 签到」`

## 错误信息

- 说清**发生了什么** + **用户能做什么**，不要抛内部错误名。
- Telegram 的原始错误（如 `PHONE_MIGRATE_5`）可以保留，但要附一句怎么办。
- 日志里可以写技术细节；界面上不行。
